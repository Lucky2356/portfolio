# Портфолио Alex

Сайт-портфолио в виде рабочего стола вымышленной ОС: проекты — иконки на столе,
их можно открывать в окнах и перетаскивать. Ниже по прокрутке — манифест,
изометрическая 3D-сцена рабочего места (ноутбук и два телефона с живым кодом на
экранах, нарисованная кодом на canvas, без видео и без библиотек) и контакты.
Отдельными страницами открываются «Работы», «Обо мне» и «Контакты».

Девять проектов подтянуты из публичных репозиториев
[github.com/Lucky2356](https://github.com/Lucky2356) — со скриншотами, задачей,
решением, результатом и метрикой у каждого.

## Что где лежит

| Путь | Что это |
|---|---|
| `Main.dc.html` | Главный артборд: вся вёрстка, стили, 3D-движок и данные проектов. Скриншоты приложений встроены в него как data-URI, сборка раскладывает их по файлам. |
| `Work.dc.html`, `About.dc.html`, `Contact.dc.html` | Остальные артборды дизайн-канваса. Сборка их не читает: страницы «Работы», «Обо мне» и «Контакты» живут внутри `Main.dc.html`. Правки в них на сайт не попадают. |
| `canvas.json` | Раскладка артбордов на канвасе. |
| `scripts/build-site.mjs` | Сборка: раскрывает шаблоны и превращает артборд в обычную HTML-страницу. |
| `tests/smoke.mjs` | Смоук-тесты собранного сайта в Chromium. |
| `portfolio-dev.html` | Готовый дизайн-канвас со всеми четырьмя артбордами. Пересобирается только инструментом Claude Design, поэтому лежит в репозитории целиком. |
| `.github/workflows/deploy.yml` | Сборка на GitHub Actions и публикация на GitHub Pages. |

Сборка (`dist/`) в репозитории не хранится — её делает CI при каждом пуше.

## Сборка

Для сборки нужен только Node.js 20+, зависимостей нет.

```bash
npm run build
```

Появится:

| Файл | Что это |
|---|---|
| `dist/index.html` | Сайт, ~230 КБ. Стили и скрипты внутри, скриншоты — рядом. |
| `dist/img/*.jpg` | Пятнадцать скриншотов, грузятся по мере прокрутки. |
| `dist/portfolio-site.html` | Тот же сайт одним файлом без `<!doctype>`, `<html>` и `<body>` — для публикации артефактом. Картинки внутри, поэтому он тяжелее. |

`dist/index.html` ссылается на `dist/img/`, поэтому открывать его нужно
с сервера — например `npx http-server dist`. Для «открыть двойным кликом»
годится `dist/portfolio-site.html`.

Сборка попутно проверяет разметку и печатает, что осталось заполнить:

- нераскрытые `{{...}}` после шаблонизатора;
- вложенность тегов (закрывающий тег не от того элемента браузер молча
  «чинит» клонированием, и вёрстка едет);
- что каждая CSS-анимация ссылается на существующий `@keyframes`;
- незаполненные контакты из `CONTACTS`.

Любая из проверок роняет сборку, поэтому до `main` такие ошибки не доходят.

## Тесты

```bash
npm ci                              # ставит playwright (только для тестов)
npx playwright install chromium
npm run build && npm test
```

`tests/smoke.mjs` поднимает собранный сайт на временном порту и прогоняет его
в настоящем Chromium: рабочий стол, панель задач, страница «Работы», терминал,
телефон 390×844, страница без JavaScript и режим `prefers-reduced-motion`.

Каждая проверка выросла из реального дефекта, поэтому файл заодно читается как
список того, что уже ломалось: подвал внутри ссылки-пилюли, одинаковые превью
у проектов без скриншотов, чёрный экран без скрипта, горизонтальная прокрутка
на телефоне, окно, которое некуда свернуть. Тесты идут в CI на каждый push
и pull request.

## Публикация на GitHub Pages

Сборка идёт при каждом пуше в `main`. Публикация выключена, пока не сделано два шага:

1. **Settings → Pages → Source: GitHub Actions**
2. **Settings → Secrets and variables → Actions → Variables → New variable:**
   `DEPLOY_PAGES` = `true`

После этого сайт будет обновляться сам на `https://lucky2356.github.io/portfolio/`.
Чтобы снова снять его с публикации, достаточно поменять переменную на `false`.

## Что осталось доделать

Всё сводится к одному объекту `CONTACTS` в начале `renderVals()`
(`Main.dc.html`). Пока значение пустое, ссылка и её кнопка на странице
не выводятся — лучше ничего, чем `hello@example.com` или кнопка
«LINKEDIN», ведущая на главную страницу LinkedIn. `npm run build`
перечисляет незаполненное в логе.

- [x] `email`, `city`, `format`, `timezone` — заполнены;
- [ ] `surname` — фамилия в подвале (`© 2026 ALEX …`) и для ATS у рекрутёра;
- [ ] `linkedin`, `telegram` — адреса профилей целиком;
- [ ] `resume` — ссылка на PDF резюме.

Отдельно:

- [ ] **Скриншоты System Hub и Telegram Job Bot** — единственные два проекта
      без картинок, у них рисуется генеративная заглушка.
- [ ] **`og:image`** — сейчас подставляется скриншот одного из проектов.
      Осмысленнее нарисовать картинку 1200×630 и положить рядом.
